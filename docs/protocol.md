# Protocol versions 1 and 2

Service: `9aa8b570-27e5-45fb-86a1-4c9608431070`.

| Characteristic | UUID suffix | Access | Payload |
| --- | --- | --- | --- |
| Identity | `b571` in the first UUID group | Read | version (1 byte), device ID (16 bytes), firmware major/minor/patch (3 bytes) |
| Challenge | `b572` | Write with response | version (1 byte), random nonce (16 bytes) |
| Response | `b573` | Read | v1: 32-byte HMAC-SHA256; v2: 8-byte uptime then 32-byte HMAC-SHA256 |

All UUIDs otherwise match the service UUID. Numeric version fields are individual unsigned bytes. Device IDs, keys and nonces are raw bytes, not ASCII hex. Config files represent IDs and keys as hex for copying.

For protocol 1, the authenticated message is the concatenation of ASCII `BLE-ARRIVAL-AUTH`, one NUL byte, the complete 20-byte identity characteristic and the 16-byte nonce. The key is 32 random bytes generated by HA. Use standard HMAC-SHA256 without truncation.

HA connects through its Bluetooth manager, reads identity, validates version and expected device ID, generates a cryptographically random nonce, writes the challenge, reads the response and uses constant-time verification. The challenge has a five-second monotonic deadline measured from creation and is consumed on first verification, including failure. Connection setup has a separate bounded timeout. No observed response or successful state is restored across restarts.

The dongle advertises the service UUID and permits one client at a time. It exposes no credential write/read characteristic. New challenges clear the previous response, malformed requests produce no response, valid requests are rate limited to one per 200 ms, responses expire after five seconds, and connections are closed after ten seconds. Response reads may use standard ATT long reads at the default MTU; challenge and identity fit the default MTU. Notifications and MTU negotiation are not required.

Discovery names and Bluetooth addresses are unauthenticated hints. Firmware version is trusted only after verification because identity is included in the HMAC. Relaying a live exchange remains possible. There is no distance bounding, mutual authentication, pairing or encryption of advertisements. Secrets are provisioned over USB.

`tests/vectors/auth_v1.json` is public deterministic test data, not a deployable credential. Both the Python verifier and the C++ message builder are tested against it. ESP-IDF's mbedTLS provides firmware HMAC.

## Protocol 2: authenticated uptime

Firmware v0.2.0 uses identity version byte 2 and firmware bytes 0, 2, 0. The challenge remains 17 bytes, beginning with version 2. The 40-byte response contains unsigned 64-bit **uptime in whole seconds, little-endian**, followed by the 32-byte MAC. The signed message is `context || identity || nonce || uptime_bytes`. HA exposes uptime only after successful constant-time MAC verification. Modifying uptime, identity or nonce invalidates the MAC. Response framing is strict.

The firmware samples `esp_timer_get_time() / 1000000` when processing the challenge. This 64-bit monotonic boot timer avoids the approximately 49-day wrap of 32-bit millisecond counters. It resets on firmware restart or power loss; it is not a vehicle ignition sensor or persistent lifetime counter. There is no extra GATT operation, time synchronisation or flash write. The 40-byte response uses the same standard ATT long-read mechanism as the original 32-byte response. Hardware latency and proxy compatibility still require testing.

HA v0.2.0 accepts protocol 1 with uptime `None` (unknown), and protocol 2 with verified uptime. The challenge version must match the identity version; a protocol 2 exchange cannot fall back to a protocol 1 MAC. Unknown versions fail closed. Old HA integrations reject protocol 2, so update HA before firmware. A genuine legacy firmware with the credential remains accepted but cannot satisfy an uptime condition.

`tests/vectors/auth_v2.json` is deterministic public test data, shared by the C++ message-builder and Python verifier tests. It includes a large uptime to check every byte of the 64-bit representation.
